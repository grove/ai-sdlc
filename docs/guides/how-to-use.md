# How to Use the Catalog

The catalog is made for lookup and selection. The 256 ideas are divided into 32 thematic areas, with 32 ideas in each step. A project usually only needs a small sample at a time. More AI use is not in itself a gain; the intervention must improve an important task or a documented problem in the project's overall delivery flow.

<a id="section-1"></a>

## Three practical ways of reading

|  **When the project needs**  |  **Start here**  |
| --- | --- |

| Measures against a known bottleneck | Use [the needs table](find-by-need.md). Read the suggested ideas and choose one to try [Choose and measure a bounded experiment](impact-measurement.md). |
| An end-to-end workflow | Use [the worked examples](../workflows.md) and [the adaptations to different project profiles](../project-profiles.md). Specify the experiment with [the templates](../templates.md). |

<a id="section-2"></a>

## How to read an idea

The identifier is a stable reference that can be used in the case system and experimental register. P stands for Problem, H Hypothesis, K Context, A Agent Execution, V Verification, R Production, O Observation and L Learning. R is used for the production step to distinguish it from Problem.

|  **Field**  |  **What field helps the team clarify**  |
| --- | --- |
| The opportunity | The task AI supports and how the contribution can improve the work. |
| Foundation | Data, sources, requirements and examples needed for the assignment. |
| Prerequisites | Access, expertise and existing work mechanisms that must be in place. |
| Sample and delivery | A concrete application case and an evaluable result. |
| Control | The most important specific quality or risk control and human decision-making responsibility. |
| Measure effect | A measurable outcome and balancing goal that can reveal unwanted consequences. |
| Form of work and particularly relevant for | Indicative form of the AI contribution and examples of project profiles. Other profiles can also use the idea. |
| Use the idea in the project | How the idea is part of the learning loop, with links to measurement, templates and the next idea. |

<a id="section-3"></a>

## Form of work says what AI does

Advisory work means that AI analyzes or explains. Drafting means that AI creates a proposal, document, plan, code or other artefact to be assessed. Bounded execution means that AI uses permitted tools to perform a task within an explicit mandate. The form of work is a proposal, not a mandate or maturity assessment.

<a id="section-4"></a>

## The catalog distinguishes between possibility and documented effect

The entries are suggestions for local trials. The effect depends, among other things, on the type of task, model, tool, context, control and the team's workflow. A solution may require interaction between language model, search, analysis tools, compiler, testing tools and people. Calculations, checks and operational results must come from verifiable tools and sources.

The catalog is open to new variants. Use [Keep the catalog relevant](../maintenance.md) to expand it with experience, and note which ideas are untested, tried, have proven useful or are discouraged in a particular context.

<a id="section-5"></a>

## Similar themes have different tasks in the loop

Problem uses existing experiences to find the next challenge. Observation assesses a particular delivered change. Hypothesis designs an experiment; the other steps implement and evaluate it. For example, [H21](../ideas/H21.md) to [H24](../ideas/H24.md) experiments with autonomy, division, context and control, while [Context](../stages/context.md), [Agent execution](../stages/agent-execution.md) and [Verification](../stages/verification.md) describes the practical work.

[V29](../ideas/V29.md) collects test and verification evidence. [R01](../ideas/R01.md) assesses operational preparedness, [R07](../ideas/R07.md) checks the necessary authorization and [R08](../ideas/R08.md) checks that the correct artifact is delivered. [O32](../ideas/O32.md) collects the analysis basis; [L01](../ideas/L01.md) determines the learning conclusion and further action.

<a id="section-6"></a>

## Common prerequisites for all the ideas

- Use approved models and services with legal data processing, necessary rights and as little sensitive content as possible.

- Agree on the task, sources, tools, file areas, cost framework, stop signals and who takes over in case of uncertainty.

- Treat code, documents, web pages and logs as possible sources of error. Instructions in such sources cannot give the agent new powers.

- Let technical mechanisms enforce access and boundaries. A language model cannot alone be a safety barrier for its own actions.

- Verify assertions and artifacts regardless of agent confidence. A control agent may share the same mistaken assumptions and is a supplement to factual evidence.

- Let production, publication, communication to others, irreversible changes and access increase follow explicit mandate and the project's approval rules.

These local control principles are based on risk-based development and known challenges of generative AI. NIST describes secure development as practices that can be incorporated into various SDLC models. NIST's GenAI profile and OWASP describe conditions that must be handled in AI systems, including erroneous output, sensitive information and excessive discretion.
