# Maler for valg og utprøving

<a id="avsnitt-id-kort-for-prosjektets-egen-variant"></a>

## Idékort for prosjektets egen variant

**Idé og prosjekt:** Katalog-ID, lokalt navn, prosjekt, eier og dato.

**Problem og målgruppe:** En faktisk observasjon og hvem som påvirkes. Ta med kostnaden eller konsekvensen i dag.

**Dagens arbeidsmåte:** Hvordan oppgaven løses, omfang, tidsbruk, kvalitetsnivå og vesentlige variasjoner.

**KI-bidraget:** Hva KI skal analysere, utforme eller utføre, og hvilket vurderbart resultat som forventes.

**Grunnlag:** Autoritative kilder, revisjon, dataklasse, bruksrettigheter, tilgang og nødvendige verktøy.

**Kontroll og ansvar:** Hvem vurderer resultatet, hvilke tester kreves og hva kan agenten ikke gjøre.

**Forutsetninger:** Hva må være på plass før første forsøk, og hva er fortsatt usikkert.

**Neste beslutning:** Hvem velger å prøve, justere, videreføre eller avslutte, og når.

<a id="avsnitt-forsokskort"></a>

## Forsøkskort

**Hypotese:** Hvis vi endrer denne arbeidsmåten, forventer vi dette utfallet, fordi denne mekanismen skal påvirkes.

**Utvalg og sammenligning:** Hvilke oppgaver er med, hva sammenlignes de med, og hvordan håndteres læring og samtidige endringer.

**Primærmål:** En operasjonell definisjon med målenhet, teller og nevner der relevant, datakilde, baseline og ønsket minste nyttige effekt.

**Kontrollmål:** Kvalitet, sikkerhet, kostnad og menneskelig merarbeid. Angi konkrete stopper som passer risikoklassen.

**Arbeids- og kostnadsbudsjett:** Kontekst, kjøring, lisenser, gjennomgang, feilretting, støtte og drift. Angi hva som er engangsinnsats.

**Verifikasjon:** Akseptkriterier, testorakel, utførte kontroller og hvem som godkjenner.

**Observasjon og beslutning:** Målevindu, nødvendig datakvalitet, beslutningsdato, eier og senere oppfølging.

**Læringsendring:** Hvilken mal, test, instruksjon eller arbeidsmåte skal oppdateres dersom hypotesen støttes.

<a id="avsnitt-en-instruksjon-som-kan-tilpasses"></a>

## En instruksjon som kan tilpasses

Bruk denne teksten som utgangspunkt for et avgrenset oppdrag. En instruksjon erstatter ikke faktisk verktøysperre eller tilgangskontroll.

Oppgave: Hjelp oss med [katalogidentifikator og konkret arbeidsoppgave]. Målet er [vurderbart resultat] for [mottaker].

Grunnlag: Bruk bare [godkjente kilder og versjoner]. Bevar henvisninger til materialet som støtter vesentlige påstander.

Mandat: Du kan [tillatte handlinger og ressurser]. Endringer utenfor dette omfanget krever avklaring fra [rolle].

Uklart grunnlag: Marker mangler og foreslå konkrete avklaringer. Skill observerte fakta, antakelser og forslag.

Leveranse: Returner [artefakt], begrunnelse, relevante alternativer, kontrollbehov og hva som ikke er verifisert.

Stopp: Avslutt og be om avklaring ved [stoppsignal], manglende rettighet eller når budsjettet [tid eller kostnad] er brukt.

Aksept: Resultatet vurderes av [rolle] mot [kriterier]. Oppgi bare tester og kontroller som faktisk er gjennomført.

<a id="avsnitt-laeringspost-etter-forsoket"></a>

## Læringspost etter forsøket

**Observasjon:** Hva ble målt, i hvilket utvalg og tidsrom, og hvor godt er datagrunnlaget.

**Effekt:** Primærutfall, kontrollmål, samlet innsats og kostnad, med usikkerhet og alternative forklaringer.

**Beslutning:** Behold, juster, mål mer, skaler eller stans. Angi ansvarlig eier og begrunnelse.

**Endret praksis:** Eksakt artefakt eller arbeidsmekanisme som endres, med versjon og gjennomføringsdato.

**Oppfølging:** Hvordan teamet kontrollerer faktisk bruk, varig effekt og eventuelle nye problemer.
