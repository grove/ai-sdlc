# Hold katalogen relevant

Utpek en katalogeier og la prosjektteam bidra med lokale varianter og læring. Bevar de stabile identifikatorene når teksten forbedres. Nye ideer kan legges til med nye ID-er, mens utgåtte oppføringer markeres med erstatning og begrunnelse. På den måten forblir tidligere eksperimenthenvisninger forståelige.

| **Lokal status** | **Hva som bør finnes** |
| --- | --- |
| Idé | Konkret oppgave, mulig nytte, nødvendig grunnlag, kontroll og forslag til måling. |
| Valgt for utprøving | Eier, hypotese, baseline eller plan for baseline, avgrensning og beslutningsdato. |
| Under utprøving | Versjonert oppsett, reelle kjøringer, avvik, kostnader og observerte utfall. |
| Dokumentert nyttig i gitt kontekst | Beslutningsgrunnlag, oppgavetype, målbar effekt, begrensninger og plan for varighet. |
| Krever tilpasning eller mer data | Hvilke forutsetninger mangler, og hvilket neste forsøk som kan avklare dem. |
| Frarådet eller avviklet i gitt kontekst | Hvorfor tiltaket ikke ga ønsket nettoeffekt, konsekvensene og eventuelle alternativer. |

<a id="avsnitt-gjor-erfaringen-gjenfinnbar"></a>

## Gjør erfaringen gjenfinnbar

Knytt katalogidentifikator til problem, hypotese, oppgave, kontekstversjon, agentkjøring, verifikasjon, levert versjon, observasjonsvindu og læringsbeslutning. Lagre relevante metadata og lenker til beskyttede kilder. En felles katalog trenger ikke råprompter, kildekode, persondata eller detaljerte sikkerhetsfunn.

<a id="avsnitt-revider-pa-grunnlag-av-faktiske-endringer"></a>

## Revider på grunnlag av faktiske endringer

Vurder oppføringer på nytt når modell, verktøy, datagrunnlag, kontrollkrav eller arbeidsmåte endres. Marker virkningen lokalt og prøv berørte oppgaver før bred videreføring. En erfaringsrapport fra ett team bør vise forutsetninger og usikkerhet, slik at et annet team kan gjøre en egen vurdering.
