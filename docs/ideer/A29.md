# A29 Skrive dokumentasjon som følger leveransen

<a id="a29"></a>

- **Steg:** [Agentutførelse](../steg/agentutforelse.md)
- **Temaområde:** [Plattform og øvrige leveranser](../steg/agentutforelse.md#a-kategori-4)
- **Arbeidsform:** Utforming
- **Særlig relevant for:** Dokumenter og beslutninger, Integrasjon, Produktutvikling

## Muligheten

KI kan oppdatere brukerhjelp, utviklerguider og API-eksempler fra en verifiserbar endring og godkjente kilder. Den kan produsere målrettet dokumentasjon samtidig med arbeidet, slik at dokumentasjonsgjeld og spørsmål fra mottakere ikke vokser etter leveransen.

## Grunnlag

Endringsdiff, kontrakter, godkjente begreper, dokumentasjonsmal og informasjon om målgruppen.

## Forutsetninger

Kilder som beskriver den konkrete versjonen og eiere som kan godkjenne innhold for målgruppen.

## Eksempel og leveranse

Et nytt API får oppdaterte eksempler og forklaring av feilsvar; agenten leverer dokumentasjonsendringer som kan prøves mot det samme bygget som implementeringen.

## Kontroll

Fageier kontrollerer riktighet og prøver kritiske eksempler; påstander om funksjoner og støtte må støttes av faktisk implementasjon.

## Mål effekt

Tid til godkjent dokumentasjon, balansert med feil i eksempler og senere støttebehov hos brukere eller utviklere.

## Bruk ideen i prosjektet

Avtal leveranse, verktøy, filområder, stoppsignaler og ansvar for gjennomgang. Ta med oppsett, menneskelig oppfølging og senere feilretting når forsøket vurderes.
