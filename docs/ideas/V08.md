# V08 Detect unintended changes in user history

<a id="v08"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Requirements and functional correctness](../stages/verification.md#v-category-1)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Product Development, Mobile and Client Software, Packaged Software

## Opportunity

AI can compare screenshots, texts and recorded user history before and after a change. It prioritizes differences that may affect task completion, rather than treating all visual deviations equally. This can make the regression review more targeted for products with many interface surfaces.

## Inputs and Evidence

Approved reference images, screen recordings, user processes, design rules, language variants and description of changes for the current version.

## Prerequisites

The team needs stable test runs, representative screen sizes and clear ownership of approved visual references.

## Example and Deliverable

After upgrading a design system, AI creates a deviation report that shows a hidden save button on a small screen and changed text in the confirmation dialog.

## Safeguards and Review

The design or product owner assesses the deviations in the actual interface. AI must not approve new reference images automatically without assessment of functional significance.

## Measuring Impact

Time to assess interface regressions, along with translating critical deviations and errors in user tasks after launch.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
