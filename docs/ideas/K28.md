# K28 Provide role-based introduction to the project

<a id="k28"></a>

- **Stage:** [Context](../stages/context.md)
- **Category:** [Maintenance and reuse of context](../stages/context.md#k-category-4)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Documents and Decisions, Platform Engineering, Maintenance

## Opportunity

AI can create a short learning path adapted to what a new developer, tester or professional should do. It can select relevant architecture, rules, tools and previous decisions, so that the introduction becomes task-oriented and easier to keep up to date.

## Inputs and Evidence

Role, first task, source catalog, introductory material, access profile and documented work processes.

## Prerequisites

Maintained basic sources and a responsible mentor who can correct suggestions and answer questions.

## Example and Deliverable

A new tester receives an introduction with a system overview, key test data, known error patterns and a first practice task with approved examples.

## Safeguards and Review

Academic mentor controls content and progression; adaptation follows role and task, without sensitive assumptions about the person.

## Measuring Impact

Time for the first independently approved assignment, together with the need for correction and translated safety instructions.

## Applying This Idea

Agree which sources, access and quality requirements apply to the specific task. Measure both the time to usable context and rework due to deficiencies or errors in the foundation.
