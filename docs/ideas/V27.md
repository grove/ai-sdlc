# V27 Give code review a targeted decision-making basis

<a id="v27"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Verification process and evidence](../stages/verification.md#v-category-4)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Product Development, Legacy Systems, Platform Engineering

## Opportunity

AI can create a review of a change diff that highlights changed behavior, important assumptions and places that require professional review. It can link questions to specific code snippets and requirements. This can make human review more focused without leaving final approval to the model.

## Inputs and Evidence

Change diffs, code contracts, architecture decisions, acceptance criteria and validated findings from tests, SAST, DAST and other security analyses.

## Prerequisites

The change must be defined, the review criteria known and the necessary context available to both humans and AI.

## Example and Deliverable

For changed cache logic, AI supplies a review guide with questions about expiration, invalidation and concurrency, including which assumptions lack test evidence.

## Safeguards and Review

Code owner evaluates the change himself and confirms findings. A control agent can share error assumptions with the author agent and is therefore considered support.

## Measuring Impact

Review time per approved change, together with relevant findings, false alarms and errors that escape the overall control process.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
