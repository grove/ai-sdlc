# R21 Adapt induction to actual user roles

<a id="r21"></a>

- **Stage:** [Production](../stages/production.md)
- **Category:** [Operational readiness and reception](../stages/production.md#r-category-3)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Product Development, Packaged Software, Documents and Decisions

## Opportunity

AI can create role-based induction courses that explain how the new function is used in a specific work task. It can combine guidance, practice data and necessary access in one plan. This supports the transition from published functionality to recipients actually being able to use it.

## Inputs and Evidence

User roles, changed work processes, approved guides, training needs, available practice environments and procedures for granting necessary access.

## Prerequisites

The work processes and user roles must be clarified, with representative users who can test the introduction before making it widely available.

## Example and Deliverable

For a new case tool, AI creates separate introduction tasks for the case manager and manager, with practice case, expected result and check that the role has the correct access.

## Safeguards and Review

The process owner validates the training with representative users. AI cannot approve its own user understanding or assign production access without established authorization.

## Measuring Impact

Time until the user completes the agreed initial task, together with errors in the training process, need for support and lack of access at start-up.

## Applying This Idea

Clarify what intended use means for the delivery, who approves the transfer and who owns the operation. Follow the introduction with measurements and a workable plan for failure.
