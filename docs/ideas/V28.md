# V28 Prioritize test order by change risk

<a id="v28"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Verification process and evidence](../stages/verification.md#v-category-4)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Platform Engineering, Product Development, Regulated Systems

## Opportunity

AI can suggest which tests should be run first based on affected dependencies, failure consequence and history. The purpose is previously relevant feedback, not to remove necessary controls. The team can thus receive faster signals about serious errors while the complete mandatory test run is still being carried out.

## Inputs and Evidence

Dependency map, test duration, previous failures, risk classification, change diff and an explicit list of tests that are always required.

## Prerequisites

The tests must have known dependencies and durations, and the CI must support reprioritization without bypassing approval requirements.

## Example and Deliverable

In the event of a change in login, AI suggests that access and session tests are run before the long report package, and delivers a reasoned schedule to the CI owner.

## Safeguards and Review

The test manager approves the prioritization. Mandatory gates are retained, and any reduction of the test scope requires separately documented risk acceptance outside the model's decision.

## Measuring Impact

Time to first relevant bug notification, along with completed mandatory test coverage and bugs overlooked due to bug prioritization.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
