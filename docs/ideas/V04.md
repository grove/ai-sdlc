# V04 Find missing limit values and negative trends

<a id="v04"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Requirements and functional correctness](../stages/verification.md#v-category-1)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Product Development, Integrations, Mobile and Client Software

## Opportunity

AI can review requirements and change diffs to suggest limit values, empty values and invalid states. It can also combine assumptions that are often tested separately. This gives the tester a prioritized list of translated situations with possible significance for the user. It can also design bounded fuzzing proposals that a test tool runs in isolation.

## Inputs and Evidence

Validation rules, data formats, error messages, existing test cases and changed fields or decision conditions in the delivery.

## Prerequisites

Input rules and expected error handling must be available, and the team needs a safe environment for negative tests.

## Example and Deliverable

For file upload, AI creates a test list of zero bytes, maximum size, wrong character set, duplicate name and aborted transfer, related to expected user results.

## Safeguards and Review

The test manager separates realistic risks from irrelevant combinations. Incriminating or malicious test data is only run in approved and isolated environments.

## Measuring Impact

New relevant errors uncovered before release, together with time spent per confirmed discovery and errors in the rejection process after production deployment.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
