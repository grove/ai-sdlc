# K03 Explain actual behavior in legacy code

<a id="k03"></a>

- **Stage:** [Context](../stages/context.md)
- **Category:** [System and domain](../stages/context.md#k-category-1)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Legacy Systems, Maintenance, Regulated Systems

## Opportunity

AI can compare older code, tests, event logs and existing documentation to explain what the system does in selected situations. It can make undocumented rules visible before the team refactors or replaces the functionality in the system.

## Inputs and Evidence

Limited legacy code, existing tests, representative logs and approved examples of input and output.

## Prerequisites

Possibility to examine code and representative examples without access to unnecessary personal data.

## Example and Deliverable

In a salary module, AI describes how dates and rounding are processed, and delivers a rule overview with specific places where the behavior is still unknown.

## Safeguards and Review

Subject owner decides if existing behavior is desired; AI must not turn a historical mistake into a new requirement.

## Measuring Impact

Time spent on understanding, balanced with errors in rule explanations and deviations discovered during later characterization tests.

## Applying This Idea

Agree which sources, access and quality requirements apply to the specific task. Measure both the time to usable context and rework due to deficiencies or errors in the foundation.
