# R11 Plan database changes to withstand the transition period

<a id="r11"></a>

- **Stage:** [Production](../stages/production.md)
- **Category:** [Deployment and activation](../stages/production.md#r-category-2)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Data and Analytics, Legacy Systems, Platform Engineering

## Opportunity

AI can help concretize expansion, transition and cleanup in the case of database changes where old and new application versions coexist. It creates checkpoints for compatibility and data integrity. This reduces the risk of an otherwise correct form change breaking working clients during the actual rollout.

## Inputs and Evidence

Database schema, migration script, application versions, compatibility requirements, proof of verification and plan for backup and recovery of relevant data.

## Prerequisites

The team must know active client versions and have tested the migration run with representative data and verifiable recovery.

## Example and Deliverable

When renaming a field, AI delivers a sequence plan for the new field, controlled data copying, client transition and deferred removal of the old field.

## Safeguards and Review

The database manager verifies the plan and approves irreversible steps. The agent must not run migrations or delete fields without explicit and limited authorization.

## Measuring Impact

Schema change manual coordination time, along with incompatible client states, data integrity discrepancies, and aborted or irreversible migration failures.

## Applying This Idea

Clarify what intended use means for the delivery, who approves the transfer and who owns the operation. Follow the introduction with measurements and a workable plan for failure.
