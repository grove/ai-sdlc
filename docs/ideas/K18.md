# K18 Distinguish trusted instructions from source content

<a id="k18"></a>

- **Stage:** [Context](../stages/context.md)
- **Category:** [Sources of data and work surface](../stages/context.md#k-category-3)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Platform Engineering, Regulated Systems, Documents and Decisions

## Opportunity

AI can help tag sources by provenance, approval status, and possible instructional content before using them as context. It makes suspicious or conflicting sources visible, while technical policy must still enforce which instructions the agent is allowed to follow.

## Inputs and Evidence

Source content, ownership status, source priority, applicable agent instructions and rules for untrusted material.

## Prerequisites

Fixed instruction hierarchy and technical boundaries that cannot be overridden by acquired content.

## Example and Deliverable

An external issue note contains a call to retrieve secrets; AI marks the passage and delivers a source assessment that is kept together with the assignment.

## Safeguards and Review

Machine access control and tool limits are independently enforced; AI classification alone does not protect against instruction injection.

## Measuring Impact

Discovered risky sources, balanced with false alerts and results from controlled tests of attack attempts.

## Applying This Idea

Agree which sources, access and quality requirements apply to the specific task. Measure both the time to usable context and rework due to deficiencies or errors in the foundation.
