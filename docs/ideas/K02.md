# K02 Find affected components before a change

<a id="k02"></a>

- **Stage:** [Context](../stages/context.md)
- **Category:** [System and domain](../stages/context.md#k-category-1)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Integrations, Legacy Systems, Data and Analytics

## Opportunity

AI can follow references between code, interface, configuration and data models to suggest which parts are affected by a planned change. The result helps the team get the right context and involve affected owners early in the work.

## Inputs and Evidence

Change description, dependency map, API contracts, database usage, consumer overview and distribution limits.

## Prerequisites

Updated contracts or ability to control dynamic links through authorized observation.

## Example and Deliverable

When a customer data field changes, AI delivers an impact list of API consumers, reports, events, and tests that the team must investigate before implementation.

## Safeguards and Review

Responsible owners confirm impact; dynamic links and external consumers are checked separately, because searches in code do not provide full coverage.

## Measuring Impact

Time to clarify the scope of changes, together with the number of late discovered dependencies and unnecessarily notified owners.

## Applying This Idea

Agree which sources, access and quality requirements apply to the specific task. Measure both the time to usable context and rework due to deficiencies or errors in the foundation.
