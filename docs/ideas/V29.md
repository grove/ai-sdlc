# V29 Gather verifiable evidence of approval

<a id="v29"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Verification process and evidence](../stages/verification.md#v-category-4)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Regulated Systems, Documents and Decisions, Embedded and OT

## Opportunity

AI can structure existing test results, review decisions and deviation processing into a consistent verification package. It can identify missing versions and references before the documentation is submitted for approval. This reduces manual collection effort without changing who actually validates the controls or accepts residual risk.

## Inputs and Evidence

Requirements identifiers, build and release identity, test results, approvals, open deviations and rules for necessary verification documentation.

## Prerequisites

Original proof must have a stable identity and owner, and the document requirements must be explicit before the package is put together.

## Example and Deliverable

For a regulated delivery, AI creates a draft evidence register that links each control point to the original report, date, code version and responsible approver.

## Safeguards and Review

The approver checks the original certificate and signs according to his own powers. AI must never fabricate test runs, certifications or closure of deviations.

## Measuring Impact

Time to complete approval package, together with missing or invalid evidence and number of audit findings due to incorrect traceability.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
