# P17 Identifying expensive areas in legacy code

<a id="p17"></a>

- **Stage:** [Problem](../stages/problem.md)
- **Category:** [Technology data and operation](../stages/problem.md#p-category-3)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Legacy Systems, Maintenance, Product Development

## Opportunity

AI can combine change history, bug reports and architecture information to pinpoint areas of code that are difficult to maintain. It can formulate bounded problems, such as fuzzy boundaries or strong coupling, rather than recommending extensive rewriting based on complexity alone.

## Inputs and Evidence

Repo, change history, error and support data, system maps and representative descriptions of actual work in the code areas.

## Prerequisites

Approved repo access, traceable history and access to developers with experience from the relevant modules.

## Example and Deliverable

Small changes in pricing rules affect many modules and tests. AI delivers a hotspot note with change patterns, documented errors and candidates for further analysis.

## Safeguards and Review

Code owner validates findings and business criticality; high complexity or many commits are not the only basis for modernization.

## Measuring Impact

Measure analysis time and confirmed maintenance issues, along with change cost, regressions and unnecessary modernization proposals from the analysis.

## Applying This Idea

Use the idea to define a problem with sources, consequence and responsible owner. Also follow up on whether the completed problem basis later leads to relevant work and better outcomes.
