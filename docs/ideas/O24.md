# O24 Monitor dependencies to models and services

<a id="o24"></a>

- **Stage:** [Observation](../stages/observation.md)
- **Category:** [Operational quality and risk](../stages/observation.md#o-category-3)
- **Operating Mode:** Advisory
- **Especially Relevant To:** AI in the product, Integrations, Platform Engineering

## Opportunity

AI can compare changes in supplier response, latency, cost, interface and errors with run outcomes. It helps the team to discover when an external service or model changes the prerequisites for the solution, even if the own application code has not changed.

## Inputs and Evidence

Version metadata, contract tests, response times, error classes, pricing basis and approved supplier messages.

## Prerequisites

Registration of supplier and model version when available as well as own contract tests.

## Example and Deliverable

A model update produces several invalid structure outputs. AI creates a change report that links the violations to the version window and evaluation results.

## Safeguards and Review

Service owner validates provider information and options. Automatic model switching must comply with data requirements, quality tests and approval.

## Measuring Impact

Time to detected supplier regression and cost per successful task, with quality and availability.

## Applying This Idea

Link the measurement to the agreed hypothesis and actual exposure to the measure. Show data gaps, alternative explanations and uncertainty before an observed change is referred to as an effect.
