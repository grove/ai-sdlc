# V16 Check that data is processed as agreed

<a id="v16"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Safety and robustness](../stages/verification.md#v-category-2)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Data and Analytics, Regulated Systems, AI in the product

## Opportunity

AI can compare data models, code and flow descriptions with agreed rules for purpose, storage and access. It points out possible deviations, such as personal data in logs or non-deletion. This supports technical control of data handling before production, with legal assessments by responsible professionals.

## Inputs and Evidence

Data classification, processing descriptions, storage rules, anonymized log samples, API contracts and tests of deletion and access.

## Prerequisites

There must be approved rules for data flow and data use as well as representative test data that can be processed properly.

## Example and Deliverable

With a new analysis service, AI creates a list of deviations where email addresses end up in error logs, with suggestions for tests of masking and deletion.

## Safeguards and Review

The privacy and security officer determines requirements and acceptance. The supporting evidence for analysis must be minimized, and genuine sensitive data must not be sent to unauthorized models.

## Measuring Impact

Data handling anomalies found before release, along with verified deletion or masking and confirmed exposures after the solution is deployed.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
