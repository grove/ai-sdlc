# V03 Check properties that should apply to many cases

<a id="v03"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Requirements and functional correctness](../stages/verification.md#v-category-1)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Product Development, Data and Analytics, Integrations

## Opportunity

AI can derive propositions for property tests and metamorphic relationships when many inputs are possible. Such tests check relationships, such as that sorting preserves all elements, rather than just certain sample answers. This can uncover errors that common sample tests overlook in complicated calculations.

## Inputs and Evidence

The function's contract, domain rules, known constraints, existing tests and tools for property-based testing.

## Prerequisites

The domain must have expressible invariants or relationships that can be checked without using the implementation as a conclusion.

## Example and Deliverable

For a currency conversion, AI proposes tests of identity conversion and tolerances for return conversion, and supplies property descriptions with explicit rounding conditions for approval.

## Safeguards and Review

A developer or domain expert validates that the properties actually apply. Random test data must be reproducible and not contain sensitive content.

## Measuring Impact

Confirmed bugs found beyond existing tests, along with false alarms and property set maintenance time across multiple changes.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
