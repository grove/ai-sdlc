# L15 Follow up on whether the team's understanding is strengthened

<a id="l15"></a>

- **Stage:** [Learning](../stages/learning.md)
- **Category:** [Maintain knowledge and competence](../stages/learning.md#l-category-2)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Product Development, Legacy Systems, Documents and Decisions

## Opportunity

AI can help mentors create tasks where developers explain architecture, review changes, and debug without copying an agent response. The team can use the experience to adjust the way of working if automation weakens the ability to understand and maintain the deliveries.

## Inputs and Evidence

Agreed learning objectives, voluntary exercises, code examples and aggregated experiences from mentoring work.

## Prerequisites

Voluntary learning practice and a clear boundary between competence development and personnel assessment.

## Example and Deliverable

The team uses a lot of generated code. AI proposes a pair exercise where the developer explains error limits and changes the solution with documented reasons.

## Safeguards and Review

Mentor assesses understanding in dialogue. Do not use automatic person ranking, hidden testing or linguistic style as a measure of competence.

## Measuring Impact

Correct independent change and explanation over time, with team safety and maintenance quality as control targets.

## Applying This Idea

Turn the learning into a concrete measure with owner and follow-up date. Keep negative findings and test the change before using it as a new standard or scaling it to more tasks.
