# O22 Detect data quality changes after delivery

<a id="o22"></a>

- **Stage:** [Observation](../stages/observation.md)
- **Category:** [Operational quality and risk](../stages/observation.md#o-category-3)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Data and Analytics, Integrations, Packaged Software

## Opportunity

AI can explain discrepancies in data contracts, missing values, distributions and reconciliations after a pipeline change. It links findings to sources and downstream uses, so that the data owner more quickly distinguishes expected business change from a technical error in the delivery.

## Inputs and Evidence

Data profiles, contracts, data origins, reconciliations, pipeline versions, and validated nonconformance examples.

## Prerequisites

Defined data contracts and comparable measurements from before and after the change.

## Example and Deliverable

A new import run produces several empty country codes. AI creates a deviation report that shows which sources and reports are affected.

## Safeguards and Review

Data owner validates deviations and origin. Do not normalize away real business changes or send identifiable rows to an unauthorized model.

## Measuring Impact

Time to clarify data quality deviations, with errors in downstream decisions and false deviation alerts.

## Applying This Idea

Link the measurement to the agreed hypothesis and actual exposure to the measure. Show data gaps, alternative explanations and uncertainty before an observed change is referred to as an effect.
