# A08 Configure rules and workflows in packaged software

<a id="a08"></a>

- **Stage:** [Agent Execution](../stages/agent-execution.md)
- **Category:** [Product and user interfaces](../stages/agent-execution.md#a-category-1)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Packaged Software, Regulated Systems, Integrations

## Opportunity

AI can translate approved process rules into proposals for configuration, forms or workflows in a packaged application. It can use supported mechanisms and describe deviations from the standard, so that the project gets a reviewable change rather than hidden customization.

## Inputs and Evidence

The vendor's configuration model, process rules, data maps, roles and upgrade restrictions.

## Prerequisites

A testable sandbox, documented vendor constraints and a responsible owner for the business process.

## Example and Deliverable

A case management system receives a draft approval flow with roles and exceptions; the agent delivers an import package to the sandbox and a change description.

## Safeguards and Review

Configuration owner approves the rules and tries them in the sandbox; production settings and access rights are not changed without approved delivery.

## Measuring Impact

Time to approved process set-up, balanced with rule deviations, maintenance work and problems during vendor upgrades.

## Applying This Idea

Define the deliverable, tools, file areas, stop signals and responsibility for review. Include setup, human follow-up and later error correction when the experiment is evaluated.
