# V10 Try to break the agent's instructions and tool limits

<a id="v10"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Safety and robustness](../stages/verification.md#v-category-2)
- **Operating Mode:** Drafting
- **Especially Relevant To:** AI in the product, Platform Engineering, Regulated Systems

## Opportunity

AI can help design adversarial tests that examine whether untrusted content affects an agent's actions. The tests may include instruction injection, persuasion and attempted data leaks. The purpose is to check actual limits for tool use and data flow under realistic load.

## Inputs and Evidence

Agent mandate, tool rights, data classes, controlled attack examples, test environment and expected behavior in case of ambiguous instructions.

## Prerequisites

Tool calls must be able to be logged and limited technically, and attack tests must be authorized in an isolated environment.

## Example and Deliverable

A test kit puts fake instructions in a README and a support case; the report shows whether the agent attempts unauthorized network calls or access to secrets.

## Safeguards and Review

The safety professional owner approves the scope. The tests use synthetic secrets and isolated endpoints, and consider tool traces rather than the agent's own explanation.

## Measuring Impact

Violation of defined tool limits per test set, along with false blocking of legitimate tasks and repeatability of findings.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
