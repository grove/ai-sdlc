# V06 Check compatibility between producers and consumers

<a id="v06"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Requirements and functional correctness](../stages/verification.md#v-category-1)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Integrations, Legacy Systems, Platform Engineering

## Opportunity

AI can compare changed interfaces with known clients and contract tests to point out compatibility violations. It examines both format, semantics and error handling. This supports earlier clarification of changes that would otherwise only fail when several systems are connected together in production.

## Inputs and Evidence

Old and new API or event contracts, consumer overview, supported versions and actual contract test results.

## Prerequisites

The team needs versioned contracts and a reasonable overview of the clients that actually need to be supported after the change.

## Example and Deliverable

When changing an order status field, AI delivers a compatibility report that points to a client that does not handle the new value and missing tests.

## Safeguards and Review

Integration owner approves compatibility requirements. Unknown consumers must be marked as uncertainty; green results for known clients do not cover the entire ecosystem.

## Measuring Impact

Time to clarify contract changes, together with the number of confirmed compatibility violations before release and integration errors afterwards.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
