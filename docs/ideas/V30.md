# V30 Try documentation as an actual work assignment

<a id="v30"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Verification process and evidence](../stages/verification.md#v-category-4)
- **Operating Mode:** Bounded Execution
- **Especially Relevant To:** Documents and Decisions, Platform Engineering, Maintenance

## Opportunity

AI can follow an installation guide, runbook or training instruction in an approved test surface and record where the procedure stops. It can also compare commands and interfaces with the current version. This reveals errors in documentation that pure language washing or textual reading often overlooks.

## Inputs and Evidence

Versioned documentation, approved test environment, expected end result, permitted commands and known prerequisites for the user role.

## Prerequisites

There must be a clean test environment and an explicit mandate that delimits tools, access and permitted side effects.

## Example and Deliverable

An agent tries the developer guide from a clean desktop and returns an error list of missing environment variables, outdated commands, and results after each step.

## Safeguards and Review

Document owner approves the changes. The execution must be isolated, use test identities and stop if the instruction requires unauthorized or irreversible operations.

## Measuring Impact

Time to successful first implementation, together with blocking documentation errors and support needs of new users of the procedure.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
