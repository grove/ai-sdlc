# R12 Coordinate switching to a new data source or platform

<a id="r12"></a>

- **Stage:** [Production](../stages/production.md)
- **Category:** [Deployment and activation](../stages/production.md#r-category-2)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Data and Analytics, Legacy Systems, Packaged Software

## Opportunity

AI can structure the actual transition between old and new data source with clear freezing points, reconciliations and ownership. It can collect implementation status and highlight unresolved deviations before the traffic is moved. This supports a controlled transition when deploying new code is not sufficient.

## Inputs and Evidence

Migration plan, reconciliation criteria, data volumes, dependent processes, time windows, recovery plan and authorized owners for each transition step.

## Prerequisites

Transition rules and ownership must be agreed, and the team needs controllable reconciliations and a realistic plan if the switch is interrupted.

## Example and Deliverable

When changing the customer register, AI creates an implementation plan with the latest synchronisation, reconciliation of active customers, approval from the data owner and controlled change of reading source.

## Safeguards and Review

Data and service owners approve reconciliation and exchange. Unexplained deviations must be dealt with before proceeding, and production data is only processed within approved limits.

## Measuring Impact

Time spent on implementation coordination, along with mismatched data, missed updates and downtime associated with the transition itself.

## Applying This Idea

Clarify what intended use means for the delivery, who approves the transfer and who owns the operation. Follow the introduction with measurements and a workable plan for failure.
