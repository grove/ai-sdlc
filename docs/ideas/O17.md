# O17 Link operational deviations to changes

<a id="o17"></a>

- **Stage:** [Observation](../stages/observation.md)
- **Category:** [Operational quality and risk](../stages/observation.md#o-category-3)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Maintenance, Platform Engineering, Integrations

## Opportunity

AI can build timelines from deployment events, bug reports, traces and configuration changes to suggest which changes should be investigated. It helps operators narrow down troubleshooting, while showing evidence that supports and undermines each possible explanation.

## Inputs and Evidence

Release identifiers, logs, distributed tracing, events and timestamps with known clock quality.

## Prerequisites

Traceability from change to running version and access to relevant operational data.

## Example and Deliverable

The error rate increases after several simultaneous deploys. AI creates an event timeline with candidate explanations and suggestions for secure, readable controls.

## Safeguards and Review

The duty officer confirms the cause before intervention. Proximity in time is not sufficient proof, and logs may contain sensitive data.

## Measuring Impact

Time to confirmed fault delineation, with incorrect cause claims and overall recovery time as control measures.

## Applying This Idea

Link the measurement to the agreed hypothesis and actual exposure to the measure. Show data gaps, alternative explanations and uncertainty before an observed change is referred to as an effect.
