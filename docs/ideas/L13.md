# L13 Building a taxonomy of agent errors

<a id="l13"></a>

- **Stage:** [Learning](../stages/learning.md)
- **Category:** [Maintain knowledge and competence](../stages/learning.md#l-category-2)
- **Operating Mode:** Advisory
- **Especially Relevant To:** AI in the product, Platform Engineering, Product Development

## Opportunity

AI can group confirmed agent errors as missing context, incorrect tool usage, fabricated sources, or incomplete testing. The taxonomy makes errors pattern-based and searchable, helping the team choose a specific countermeasure rather than a general stricter prompt.

## Inputs and Evidence

Validated deviations, run data, context versions, verification findings and human takeover.

## Prerequisites

A representative selection of errors and access to the necessary runtime context without unnecessary raw content.

## Example and Deliverable

An agent misunderstands multiple return contracts. AI creates a fault type with representative examples, affected tasks and proposals for targeted contract testing.

## Safeguards and Review

Professionals check the categories and ambiguous cases. Do not mix model errors with errors in requirements, tools or data bases.

## Measuring Impact

Recurrence rate per confirmed fault type, with classification accuracy and cost of proposed measures.

## Applying This Idea

Turn the learning into a concrete measure with owner and follow-up date. Keep negative findings and test the change before using it as a new standard or scaling it to more tasks.
