# A22 Build limited AI functions into a product

<a id="a22"></a>

- **Stage:** [Agent Execution](../stages/agent-execution.md)
- **Category:** [Data integrations and test artifacts](../stages/agent-execution.md#a-category-3)
- **Operating Mode:** Bounded Execution
- **Especially Relevant To:** AI in the product, Product Development, Data and Analytics

## Opportunity

An agent can implement components for document retrieval, model invocation, source display, and structured responses following an approved solution design. It can make cost limits and error handling concrete, so that the team gets an evaluable product proposal with visible limitations more quickly.

## Inputs and Evidence

Product requirements, approved models, source areas, access rules, response contract and evaluation basis.

## Prerequisites

Approved processing of source data and an evaluation that covers actual user tasks and risk scenarios.

## Example and Deliverable

An internal supervisor receives a source-restricted search, document references and a notification when the supporting evidence is lacking; the agent provides code, configuration, and a clear error response format.

## Safeguards and Review

Product Owner and Safety Officer approve design; access and tool limits are technically enforced, and product behavior is independently evaluated.

## Measuring Impact

Time to evaluable function, balanced with incorrect answers, access violations, response time and cost per user task.

## Applying This Idea

Define the deliverable, tools, file areas, stop signals and responsibility for review. Include setup, human follow-up and later error correction when the experiment is evaluated.
