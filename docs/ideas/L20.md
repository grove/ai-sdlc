# L20 Simplify the tools the agent uses

<a id="l20"></a>

- **Stage:** [Learning](../stages/learning.md)
- **Category:** [Improve agents and work tools](../stages/learning.md#l-category-3)
- **Operating Mode:** Drafting
- **Especially Relevant To:** AI in the product, Platform Engineering, Integrations

## Opportunity

AI can analyze failed tool calls and suggest clearer forms, smaller scope of functions and more comprehensible error messages. It can reduce misunderstandings and the need for human rescue, while making the tools easier to test and limit.

## Inputs and Evidence

Tool form, validated errors, usage logs, authorization rules and known work tasks.

## Prerequisites

Access to verified tool code and representative errors with known expected results.

## Example and Deliverable

An agent confuses reading with updating. AI proposes separate interfaces and a test suite that rejects ambiguous or unauthorized operations.

## Safeguards and Review

Tool owner reviews the contract and security. Don't give wider access to hide unclear interfaces or frequent rejections.

## Measuring Impact

Proportion of correct allowed tool calls, with unauthorized side effects and necessary human takeover.

## Applying This Idea

Turn the learning into a concrete measure with owner and follow-up date. Keep negative findings and test the change before using it as a new standard or scaling it to more tasks.
