# R14 Prepare distribution through app and client channels

<a id="r14"></a>

- **Stage:** [Production](../stages/production.md)
- **Category:** [Deployment and activation](../stages/production.md#r-category-2)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Mobile and Client Software, Product Development, Embedded and OT

## Opportunity

AI can collect necessary information for signing, channel selection, step-by-step availability and recipient information for client releases. It can detect differences between package, configuration and publishing text. This reduces administrative work in distribution runs where users' installed versions are updated at different times and in different channels.

## Inputs and Evidence

Verified client packages, support policies, publishing requirements, signing status, server compatibility, and approved changes and restrictions information.

## Prerequisites

Distribution channels, signing process and support requirements must be established, with version tracking linking the package to approved test certificates.

## Example and Deliverable

For a mobile app, AI creates a check-in list with package version, supported system versions, release information and confirmation that the server supports both old and new clients.

## Safeguards and Review

Release owner approves submission and publication. Signing keys are handled by secure services, and AI must not assume that all users upgrade at the same time.

## Measuring Impact

Time to approved client publishing, along with rejected submissions, package and text discrepancies, and violations for clients not yet updated.

## Applying This Idea

Clarify what intended use means for the delivery, who approves the transfer and who owns the operation. Follow the introduction with measurements and a workable plan for failure.
