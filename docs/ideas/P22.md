# P22 Prioritize documented security exposures

<a id="p22"></a>

- **Stage:** [Problem](../stages/problem.md)
- **Category:** [Technology data and operation](../stages/problem.md#p-category-3)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Platform Engineering, Product Development, Regulated Systems, Maintenance

## Opportunity

AI can structure existing security findings and connect them to actual exposure, data and service meaning. It can collect duplicates and clarify which information is missing, so that the security manager more quickly gets a verifiable basis for prioritizing remedial problems.

## Inputs and Evidence

Validated scanner findings, component overview, ownership, data classes, network exposure and the organization's current assessment of severity and residual risk.

## Prerequisites

Approved security data access, updated component overview and professional capacity to verify exposure and consequence.

## Example and Deliverable

Many package finds touch the same shared component. AI creates an exposure note with service links, confirmed use and open questions for the security officer before measures are prioritized.

## Safeguards and Review

Security owner approves priority; AI cannot close discoveries, declare exploitability or reduce risk without technical proof.

## Measuring Impact

Measure time for validated prioritization, together with translated serious findings and erroneous down-prioritization in the selection.

## Applying This Idea

Use the idea to define a problem with sources, consequence and responsible owner. Also follow up on whether the completed problem basis later leads to relevant work and better outcomes.
