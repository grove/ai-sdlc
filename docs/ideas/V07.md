# V07 Compare old and new solution when migrating

<a id="v07"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Requirements and functional correctness](../stages/verification.md#v-category-1)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Legacy Systems, Data and Analytics, Packaged Software

## Opportunity

AI can help design comparisons between old and new implementations on representative inputs. It categorizes deviations and suggests which differences may be due to intentional changes. This makes migration risk more visible than an assessment based only on unit tests.

## Inputs and Evidence

Representative anonymised data base, old and new implementation, expected differences and observable functional outputs.

## Prerequisites

The solutions must be comparably runnable, and the team must have documented which changes in behavior are intended.

## Example and Deliverable

When replacing a price calculation engine, AI groups deviations from parallel driving and delivers a list of deviations that separates rounding from missing discount rules.

## Safeguards and Review

The domain expert determines which differences are permitted. The old solution is also not considered correct if known errors are to be corrected.

## Measuring Impact

Time to classify migration discrepancies, along with unexplained differences and errors in retained functionality after the transition.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
