# V31 Prepare realistic tests for user acceptance

<a id="v31"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Verification process and evidence](../stages/verification.md#v-category-4)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Product Development, Packaged Software, Mobile and Client Software

## Opportunity

AI can translate user needs and process descriptions into concrete tasks for acceptance testing. It suggests variations in experience, role and situation and helps distinguish product defects from unclear tasks. This makes the preparation more systematic, while actual user acceptance still comes from relevant people.

## Inputs and Evidence

User needs, role descriptions, critical tasks, acceptance criteria, realistic test data and previous feedback from actual users.

## Prerequisites

The team must have access to representative users or recipients and know which tasks should be acceptable.

## Example and Deliverable

For a case management solution, AI creates a task set with initial registration, correction of errors and transfer to a colleague, as well as a form for observed obstacles.

## Safeguards and Review

The product owner and user representatives validate the tasks. Synthetic person responses do not substitute for empirical user insights or endorsement from the actual recipient.

## Measuring Impact

Preparation time for acceptance testing, along with actual task completion, serious user obstacles and rework discovered after formal acceptance.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
