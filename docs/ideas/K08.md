# K08 Describe the user journey and accessibility needs

<a id="k08"></a>

- **Stage:** [Context](../stages/context.md)
- **Category:** [System and domain](../stages/context.md#k-category-1)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Product Development, Mobile and Client Software, Documents and Decisions

## Opportunity

AI can collect relevant user tasks, interface patterns and accessibility requirements for the context of a change. It can highlight where a function is part of a larger journey, and which users or situations the implementation must take into account.

## Inputs and Evidence

Approved user journeys, design system, research findings, language needs and documented accessibility requirements.

## Prerequisites

Existing user insight or a clarified need for collection before assumptions are treated as requirements.

## Example and Deliverable

Before a form is built, AI creates a context of use with keyboard navigation, error situations, small screens and the transition back to the main task after registration is complete.

## Safeguards and Review

Design and subject managers confirm actual needs; synthetic personas do not replace user insight or testing with relevant users.

## Measuring Impact

Time for clarified interaction, together with accessibility deviations and rework from translated user needs.

## Applying This Idea

Agree which sources, access and quality requirements apply to the specific task. Measure both the time to usable context and rework due to deficiencies or errors in the foundation.
