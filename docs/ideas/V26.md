# V26 Investigate whether the tests actually detect errors

<a id="v26"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Verification process and evidence](../stages/verification.md#v-category-4)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Product Development, Legacy Systems, Regulated Systems

## Opportunity

AI can help select realistic code changes or error mutations that challenge the sensitivity of the test set. It analyzes undetected mutations and proposes stronger claims. This provides a better basis than high test coverage alone when the team assesses whether the tests protect important behavior.

## Inputs and Evidence

Test sets, coverage reports, domain-critical decisions, tools for mutation testing and examples of previous failures in the solution.

## Prerequisites

The tests need to be runnable and stable, and the team needs a controlled method to inject representative bugs.

## Example and Deliverable

For a calculation, a change from greater than to greater than or equal to survives; AI proposes a limit value case and explains the lack of control.

## Safeguards and Review

The tester distinguishes meaningful mutations from equivalent or irrelevant changes. AI must not make the tests dependent on internal details unnecessarily.

## Measuring Impact

Relevant error mutations detected by the tests, together with test maintenance time and false errors after legitimate implementation changes in later deliveries.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
