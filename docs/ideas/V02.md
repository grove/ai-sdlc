# V02 Clarify what is a correct result

<a id="v02"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Requirements and functional correctness](../stages/verification.md#v-category-1)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Product Development, Packaged Software, Regulated Systems

## Opportunity

AI can find ambiguities in the tests' expected results and suggest an explicit test oracle. It brings together requirements, domain rules and examples to make disagreement visible before the developers' own implementation is used as a conclusion. This can reduce false reassurance from self-confirming tests.

## Inputs and Evidence

Domain rules, approved examples, acceptance criteria, existing expectation values and questions that have arisen during development.

## Prerequisites

The team must have access to a responsible domain expert and authoritative rules for relevant decisions.

## Example and Deliverable

When calculating delivery time, AI proposes a decision table for public holidays, time zones and orders after closing time; the domain expert approves the expected values ​​before the test is run.

## Safeguards and Review

Subject owner determines the conclusion. AI must notice unresolved contradictions and must not change expected values ​​in order to get the implementation approved.

## Measuring Impact

Time spent on clarifying the expected result, together with the proportion of tests with a professionally approved conclusion and later domain errors.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
