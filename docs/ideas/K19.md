# K19 Restrict context to authorized sources

<a id="k19"></a>

- **Stage:** [Context](../stages/context.md)
- **Category:** [Sources of data and work surface](../stages/context.md#k-category-3)
- **Operating Mode:** Bounded Execution
- **Especially Relevant To:** Regulated Systems, Platform Engineering, Packaged Software

## Opportunity

AI can propose a relevant source selection within the rights of the user and the task and make lack of access visible. An access-controlled retrieval link prevents an otherwise useful search agent from mixing customers, business areas or documents with different confidentiality levels.

## Inputs and Evidence

User and task identity, source directory, access rules, tenant limits and document classification.

## Prerequisites

Integrations that pass correct identity and can filter or reject sources before content reaches the model.

## Example and Deliverable

A consulting agent builds context for one customer repository; missing architecture documents are shown as access holes, while material from other customers is never collected.

## Safeguards and Review

IAM and source system enforce rights deterministically; responsible owner determines access extensions, not the language model.

## Measuring Impact

Relevant context available at startup, along with access anomalies and false rejection of authorized sources.

## Applying This Idea

Agree which sources, access and quality requirements apply to the specific task. Measure both the time to usable context and rework due to deficiencies or errors in the foundation.
