# K20 Reduce sensitive information in context

<a id="k20"></a>

- **Stage:** [Context](../stages/context.md)
- **Category:** [Sources of data and work surface](../stages/context.md#k-category-3)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Data and Analytics, Regulated Systems, Maintenance

## Opportunity

AI can assist in identifying unnecessary sensitive fields and suggest masking or synthetic examples before material is shared. This can make several tasks practically possible within approved data limits, but requires control of what is actually removed.

## Inputs and Evidence

Data class rules, restricted material in an approved environment, the need for analysis and masking rules.

## Prerequisites

Approved processing environment and technical mechanisms that check output data before any external use.

## Example and Deliverable

Before troubleshooting a form, AI suggests which fields can be replaced with synthetic values and supplies an anonymized test example for checking.

## Safeguards and Review

Sensitive raw data is only processed in an approved environment; DLP and professional assessment check that masking does not leave identifiable information.

## Measuring Impact

Time to approved test basis, balanced with leakage risk, error masking and loss of necessary property variation.

## Applying This Idea

Agree which sources, access and quality requirements apply to the specific task. Measure both the time to usable context and rework due to deficiencies or errors in the foundation.
