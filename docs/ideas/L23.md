# L23 Develop a representative evaluation set

<a id="l23"></a>

- **Stage:** [Learning](../stages/learning.md)
- **Category:** [Improve agents and work tools](../stages/learning.md#l-category-3)
- **Operating Mode:** Drafting
- **Especially Relevant To:** AI in the product, Data and Analytics, Regulated Systems

## Opportunity

AI can suggest new test tasks from confirmed bugs, unusual user needs and recent changes. The evaluation set is maintained with degree of difficulty, basis for conclusions and validity, so that improvements are measured on real work rather than a narrow set of known demonstrations.

## Inputs and Evidence

Representative tasks, validated errors, domain changes, existing evaluations and expected outcomes.

## Prerequisites

Subject experts and a versioned set containing both success, failure and expected stop.

## Example and Deliverable

An agent fails on an old protocol variant. AI creates an anonymised evaluation proposal with test data, expected escalation and assessment criteria.

## Safeguards and Review

Subject expert validates the assignment and keeps evaluation separate from training and instructional examples. Do not use the same agent as the only conclusion.

## Measuring Impact

Coverage of relevant errors and work classes, with summary quality, test leakage and evaluation cost.

## Applying This Idea

Turn the learning into a concrete measure with owner and follow-up date. Keep negative findings and test the change before using it as a new standard or scaling it to more tasks.
