# O03 Measuring time use by end users

<a id="o03"></a>

- **Stage:** [Observation](../stages/observation.md)
- **Category:** [Users and business outcomes](../stages/observation.md#o-category-1)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Product Development, Packaged Software, Maintenance

## Opportunity

AI can link work metrics and user feedback to changes in a solution to estimate whether the end user is getting work done faster. The analysis separates active task time, waiting and follow-up work, and describes when the conditions for comparison do not hold.

## Inputs and Evidence

Representative work samples, process events, task type, error reopenings and documented start and end points.

## Prerequisites

Access to representative measurements and a task definition that is the same before and after.

## Example and Deliverable

A new case picture will save time. AI prepares a comparison report for similar case types, including additional corrections and the learning period.

## Safeguards and Review

Process owner validates selection and working time definition. Do not use click counts or open tabs as direct measures of actual effort.

## Measuring Impact

Active time per correctly completed user task, with error correction time and user experience as control measures.

## Applying This Idea

Link the measurement to the agreed hypothesis and actual exposure to the measure. Show data gaps, alternative explanations and uncertainty before an observed change is referred to as an effect.
