# H22 Testing the appropriate task size for the agent

<a id="h22"></a>

- **Stage:** [Hypothesis](../stages/hypothesis.md)
- **Category:** [Economy capacity and working methods](../stages/hypothesis.md#h-category-3)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Product Development, Legacy Systems, Integrations, Documents and Decisions

## Opportunity

AI can propose how a work task is divided into defined units with controllable results. It can design an experiment that compares larger and smaller agent tasks, so that the team examines the balance between context loss, coordination, control effort, and the ability to complete.

## Inputs and Evidence

Task description, dependencies, acceptance criteria, agent limitations and history of interruptions, errors or human assistance in similar tasks.

## Prerequisites

Explicit delivery limits, possibility to track overall work and representative tasks of comparable complexity.

## Example and Deliverable

A major API change is split into contract, implementation and documentation. AI creates a comparison plan for overall assignments against sub-assignments with targets for the end result.

## Safeguards and Review

Technical manager confirms meaningful boundaries; several completed sub-tasks shall not be counted as a greater value than the same overall delivery.

## Measuring Impact

Measure time to appropriate breakdown, together with total delivery time, integration errors and extra coordination between sub-tasks.

## Applying This Idea

Turn the idea into a limited experiment with hypothesis, basis for comparison and decision rules. Record the expected value, control needs and uncertainty before the results are available.
