# K12 Gather relevant security context

<a id="k12"></a>

- **Stage:** [Context](../stages/context.md)
- **Category:** [Requirements and task understanding](../stages/context.md#k-category-2)
- **Operating Mode:** Advisory
- **Especially Relevant To:** Regulated Systems, Product Development, Platform Engineering

## Opportunity

AI can find relevant threats, trust boundaries, access rules and security patterns for a particular change. A short, task-oriented security basis makes it easier to incorporate necessary considerations before implementation and to target the subsequent professional control.

## Inputs and Evidence

Threat models, data classes, authentication patterns, authorization rules and approved security standards.

## Prerequisites

Approved security sources and access to a professional for assessment of consequences and residual security.

## Example and Deliverable

With a new administration interface, AI provides a security context with roles, abuse cases, audit trails and which server controls the implementation must support.

## Safeguards and Review

The security officer assesses critical requirements; AI cannot declare the solution secure or approve exceptions to the security policy.

## Measuring Impact

Time for clarified safety design, balanced with late safety findings and missing critical control requirements.

## Applying This Idea

Agree which sources, access and quality requirements apply to the specific task. Measure both the time to usable context and rework due to deficiencies or errors in the foundation.
