# A03 Build interfaces with approved components

<a id="a03"></a>

- **Stage:** [Agent Execution](../stages/agent-execution.md)
- **Category:** [Product and user interfaces](../stages/agent-execution.md#a-category-1)
- **Operating Mode:** Bounded Execution
- **Especially Relevant To:** Product Development, Mobile and Client Software, Packaged Software

## Opportunity

AI can assemble screens and state management using an established design system. It can produce component code and examples for empty, loading, and failing states, so the team avoids rebuilding common patterns.

## Inputs and Evidence

Design sketches, component libraries, approved visual style, API contracts and screen state requirements.

## Prerequisites

A usable component library and the opportunity to see and try the result in the right client environment.

## Example and Deliverable

An administration page gets table, search and editing from existing components; the delivery includes code and demonstrations of load state, empty list and server errors.

## Safeguards and Review

Design and development controls interaction and compliance; visual similarity alone is not sufficient approval.

## Measuring Impact

Time to approved screenshot, balanced with usability errors, availability deviations and maintenance of new components.

## Applying This Idea

Define the deliverable, tools, file areas, stop signals and responsibility for review. Include setup, human follow-up and later error correction when the experiment is evaluated.
