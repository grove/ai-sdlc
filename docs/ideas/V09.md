# V09 Control authorization across roles and objects

<a id="v09"></a>

- **Stage:** [Verification](../stages/verification.md)
- **Category:** [Safety and robustness](../stages/verification.md#v-category-2)
- **Operating Mode:** Drafting
- **Especially Relevant To:** Product Development, Regulated Systems, Integrations

## Opportunity

AI can connect change diffs and access rules to a matrix of who gets to perform which actions. It suggests negative tests for objects, roles and organizational boundaries. This supports verification of access control which is easily overlooked when only the normal user is tested in positive processes.

## Inputs and Evidence

Role model, ownership rules, changed endpoints, test identities and descriptions of tenant or organizational boundaries.

## Prerequisites

The authorization rules must be explicit, and an approved test environment must have realistic roles and separate data areas.

## Example and Deliverable

For a case archive, AI creates a test matrix where a case manager attempts to read attachments from another department, including direct object links.

## Safeguards and Review

The safety officer approves the tests and expectations. Only authorized test identities and data are used; AI does not get free access to production information.

## Measuring Impact

Access control bugs found before release, along with coverage of defined role limits and confirmed access anomalies after delivery.

## Applying This Idea

Agree what is a correct result and what independent evidence the approval requires. Measure the inspection effort together with errors that are detected, errors that are overlooked and unnecessary rejections.
