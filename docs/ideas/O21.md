# O21 Follow the agents' access usage and deviations

<a id="o21"></a>

- **Stage:** [Observation](../stages/observation.md)
- **Category:** [Operational quality and risk](../stages/observation.md#o-category-3)
- **Operating Mode:** Advisory
- **Especially Relevant To:** AI in the product, Platform Engineering, Regulated Systems

## Opportunity

AI can summarize tool calls, access denials and policy events to uncover unexpected patterns of action. It can prioritize suspicious sequences for investigation and determine whether a new instruction or data source leads to more attempted actions outside the mandate.

## Inputs and Evidence

Agent execution logs, authorization logs, policy versions and events from approved security monitoring.

## Prerequisites

Independently enforced permissions and logs with required metadata without secrets.

## Example and Deliverable

An agent starts suggesting external calls. AI creates a deviation report with run identifier, used source and actually blocked tool actions.

## Safeguards and Review

The security officer validates findings. Access control is enforced outside the language model, and the analysis does not get its own extended privileges.

## Measuring Impact

Time to validated detection of policy deviations, with false alarms and actual unauthorized exposure.

## Applying This Idea

Link the measurement to the agreed hypothesis and actual exposure to the measure. Show data gaps, alternative explanations and uncertainty before an observed change is referred to as an effect.
